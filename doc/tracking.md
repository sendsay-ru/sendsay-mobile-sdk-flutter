Вы можете отслеживать события в CDP Sendsay, чтобы узнать больше о моделях использования вашего приложения и сегментировать клиентов по их взаимодействиям.

По умолчанию SDK автоматически отслеживает определенные события, в том числе:

* Установка (после установки приложения и после вызова [anonymize](#анонимизировать-обезличить))
* Начало и окончание сеанса пользователя
* Событие баннера для отображения сообщения в приложении или блока контента

Кроме того, вы можете отслеживать любые пользовательские события, имеющие отношение к вашему бизнесу.

> 👍
>
> Все примеры на этой странице предполагают, что `SendsayPlugin` доступен как `_plugin`. Подробности см. в разделе [Инициализация SDK](https://docs.sendsay.ru/sources-and-events/mobile-app/#%D0%B8%D0%BD%D1%82%D0%B5%D0%B3%D1%80%D0%B0%D1%86%D0%B8%D1%8F-%D1%81-%D0%BF%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5%D0%BC-%D1%87%D0%B5%D1%80%D0%B5%D0%B7-sdk).

## События

### Отслеживание событий

Используйте метод `trackEvent()` с объектом `Event` в качестве аргумента для отслеживания любого типа пользовательского события, имеющего отношение к вашему бизнесу.

Вы можете использовать любое название для типа пользовательского события. Мы рекомендуем использовать избыточное и понятное для человека название события.

Обзор часто используемых пользовательских событий см. в документации [Пользовательские события](https://sendsay.ru/api/api.html#%D0%A1%D0%BE%D0%B1%D1%8B%D1%82%D0%B8%D1%8F).

#### Аргументы

| Имя  | Тип               | Описание |
| ----- |-------------------| ----------- |
| event | [Event](#Событие) | Объект события. |

##### Событие

| Имя                | Тип                 | Описание |
| --------------------| -------------------- | ----------- |
| name **(обязательно)** | Строка               | Имя типа события, например `screen_view`. |
| свойства          | Map<String, dynamic> | Словарь свойств события. |
| временная метка           | DateTime?            | Временная метка Unix (в секундах), указывающая, когда было отслежено событие. По умолчанию используется текущее время. |

#### Примеры

Предположим, вы хотите отслеживать, какие экраны просматривает клиент. Для этого можно создать настраиваемое событие `screen_view`.

Сначала создайте `Event` с именем и свойствами, которые вы хотите отслеживать с помощью этого события. В нашем примере вы хотите отслеживать название экрана, поэтому включаете свойство `screen_name` вместе с другими соответствующими свойствами:

```dart
final event = Event(
  name: 'screen_view',
  properties: {
    'screen_name': "dashboard",
    'other_property': 123.45,
  },
);
```

Передайте объект события в `trackEvent()` следующим образом:

```dart
_plugin.trackEvent(event);
```

Второй пример ниже показывает, как при необходимости можно использовать вложенную структуру для сложных свойств:

```dart
final event = Event(
  name: 'purchase',
  properties: {
    'purchase_status': "success",
    'product_list': [
        {'product_id': 'abc123', 'quantity': 2},
        {'product_id': 'abc456', 'quantity': 1}
    ],
    'total_price': 7.99,
  },
);
_plugin.trackEvent(event);
```

> 👍
>
> При желании вы можете указать собственный `timestamp`, если событие произошло в другое время. По умолчанию будет использоваться текущее время. 

#### SSEC (События модуля "Продажи")

Обратитесь к документации [События модуля "Продажи"](https://docs.sendsay.ru/ecom/how-to-configure-data-transfer).

```dart
final DateFormat formatter = DateFormat("yyyy-MM-dd HH:mm:ss");
final String currentDateTime = formatter.format(DateTime.now());

final event = SSECEvent(
        type: TrackingSSECType.viewProduct,
        data: TrackSSEC.viewProduct()
            .product(
                id: "123456",
                datetime: currentDateTime,
                name: "Notebook",
                price: 1.0,
            ).buildData(),
    );
_plugin.trackSSECEvent(event.toSsecMap())
```

#### CCE (Пользовательские события) [в разработке]

```dart
    final Map properties = {};
    final customJsonString = """{
            'property': '5s',
            'int': 12,
            'double': 34.56,
            'string': 'test'
        }""".trim();
    const eventType = "custom_event_name";

    properties["cce"] = customJsonString;

    // Отправка события
    const event = Event(
      name: eventType,
      properties: properties,
    );
    await _plugin.trackEvent(event);
```

## Клиенты

Идентификация ваших клиентов позволяет отслеживать их на разных устройствах и платформах, улучшая качество ваших данных о клиентах.

Без идентификации события отслеживаются для анонимного клиента, идентифицируемого только по файлу cookie. Как только клиент идентифицируется по жесткому ID, эти события будут перенесены на вновь идентифицированного клиента.

> 👍
>
> Имейте в виду, что, хотя пользователь приложения и запись о клиенте могут быть связаны мягким или жестким идентификатором, они являются отдельными сущностями, каждая со своим собственным жизненным циклом. Подумайте, как связаны их жизненные циклы и когда использовать [identify](#идентификация) и [anonymize](#анонимизировать-обезличить).

### Идентификация

Используйте метод `identifyCustomer()` с объектом `Customer` в качестве аргумента, чтобы идентифицировать клиента по его уникальному жесткому идентификатору.

По умолчанию жестким идентификатором является `registered`, и его значением обычно является адрес электронной почты клиента. Однако в вашем проекте CDP Sendsay может быть определен другой жесткий идентификатор.

При желании вы можете отслеживать дополнительные свойства клиента, такие как имя и фамилия, возраст и т. д.

#### Аргументы

| Имя                     | Тип               | Описание |
| ------------------------ |-------------------| ----------- |
| customer **(обязательно)**  | [Клиент](#Клиент) | Объект клиента. |

##### Клиент

| Имя               | Тип                 | Описание |
| -------------------| -------------------- | ---------- - |
| ids **(обязательно)** | Map<String, String>  | Словарь уникальных идентификаторов клиентов. Принимаются только идентификаторы, определенные в проекте CDP Sendsay. |
| properties         | Map<String, dynamic> | Словарь свойств клиентов. |

#### Передача данных в профиль клиента (member.set)

Обратитесь к документации [метода member.set SendsayAPI](https://sendsay.ru/api/api.html#%D0%A1%D0%BE%D0%B7%D0%B4%D0%B0%D1%82%D1%8C-%D0%BF%D0%BE%D0%B4%D0%BF%D0%B8%D1%81%D1%87%D0%B8%D0%BA%D0%B0-%D0%9E%D0%B1%D0%BD%D0%BE%D0%B2%D0%B8%D1%82%D1%8C-%D0%B4%D0%B0%D0%BD%D0%BD%D1%8B%D0%B5-%D0%BF%D0%BE%D0%B4%D0%BF%D0%B8%D1%81%D1%87%D0%B8%D0%BA%D0%B0-%D0%9A%D0%94).

#### Примеры

Сначала создайте объект `Customer`, содержащий как минимум один идентификатор клиента и, опционально, словарь с дополнительными свойствами клиента:

```dart

final customer = Customer(
    ids: {
      'registered': 'jane.doe@example.com',
    },
    properties: [
      "dk": {
        'first_name': 'Jane',
        'last_name': 'Doe',
        'age', 32
      },
      "datakey": [
        ["propertyName", "set/update/delete" + ".copy"(optional), "value/newValue"],
        // пример возможных(не всех) значений установки/обновления/удаления строкового свойства
        ["anotherPropertyName", "update.copy", 123]
        // рабочий пример обновления числового свойства
      ]
    ]
);
```

> ❗️
> Оба способа - и dk и datakey - можно использовать как по отдельности так и вместе
>
> Указанное в datakey исполняется после указанного в dk
> Любая ошибка при изменении данных приводит к тому, что они не меняются вообще.

Созданные словари нужно передать в `identifyCustomer()`:

```dart
_plugin.identifyCustomer(customer);
```

Если вы хотите обновить только идентификатор клиента без дополнительных свойств, вы можете передать пустой словарь в `properties`:

```dart
final customer = Customer(
  ids: {
    'registered': 'jane.doe@example.com',
  },
  properties: {},
);
_plugin.identifyCustomer(customer);
```

### Анонимизировать (обезличить)

Используйте метод `anonymize()`, чтобы удалить всю информацию, хранящуюся локально, и сбросить текущее состояние SDK. Типичный случай использования — когда пользователь выходит из приложения.

Вызов этого метода приведет к следующим действиям SDK:

* Удаление токена push-уведомлений для текущего клиента из локального хранилища устройства и профиля клиента в CDP Sendsay.
* Очистка локальных репозиториев и кэшей, за исключением отслеживаемых событий.
* Отслеживание начала новой сессии, если включена функция `automaticSessionTracking`.
* Создание новой записи клиента в CDP Sendsay (генерируется новый мягкий идентификатор `cookie`).
* Присвоение предыдущего токена push-уведомлений новой записи клиента.
* Отслеживание нового события `installation` для нового клиента.

Вы также можете использовать метод `anonymize` для перехода к другому проекту CDP Sendsay. SDK будет отслеживать события в новой записи клиента в новом проекте, аналогично первой сессии приложения после установки на новом устройстве.

#### Примеры

```dart
_plugin.anonymize();
```

Переключиться на другой проект:

```dart
final configChange = SendsayConfigurationChange(
  project: SendsayProject(
    projectToken: 'new-project-token',
    authorizationToken: 'new-authorization-token',
  ),
  mapping: {
    EventType.payment: [
      SendsayProject(
        projectToken: 'special-project-for-payments',
        authorizationToken: 'payment-authorization-token',
        baseUrl: 'https://api-payments.some-domain.com',
      ),
    ],
  },
);
_plugin.anonymize(configChange);
```

## Сессии

SDK по умолчанию автоматически отслеживает сессии, генерируя два события: `session_start` и `session_end`.

Сессия представляет собой фактическое время, проведенное в приложении. Она начинается при запуске приложения и заканчивается, когда оно переходит в фоновый режим. Если пользователь возвращается в приложение до истечения времени сессии, приложение продолжит текущую сессию.

По умолчанию время ожидания сессии составляет 60 секунд. Установите `sessionTimeout` в [конфигурации SDK](../doc/configuration.md), чтобы указать другое время ожидания.

### Отслеживание сеанса вручную

Чтобы отключить автоматическое отслеживание сеансов, установите значение `automaticSessionTracking` равным `false` в [конфигурации SDK](../doc/configuration.md).

Используйте методы `trackSessionStart()` и `trackSessionEnd()` для отслеживания сеансов вручную.

#### Примеры

```dart
_plugin_.trackSessionStart()
```

```dart
_plugin_.trackSessionEnd()
```

### Переопределение стандартных/базовых событий в properties

SDK автоматически отслеживает ряд свойств по умолчанию для событий `session_start` и `session_end`, включая `ip`, `city`, `country` и т. д.

Вы можете переопределить значение любого из этих свойств, включив их в параметр конфигурации `defaultProperties` (см. ниже). Например, если вы не хотите отслеживать IP-адреса клиентов, вы можете установить значение по умолчанию свойства `ip` равным пустой строке.

## Push-уведомления

Если разработчики [интегрируют функцию push-уведомлений](../doc/push-notifications.md#integration) в свое приложение, SDK по умолчанию автоматически отслеживает токен push-уведомлений.

В Android вы можете отключить автоматическое отслеживание push-уведомлений, установив булево значение свойства `automaticPushNotification` в `false` в [конфигурации SDK для Android](../doc/configuration.md#android-specific-configuration-parameters). После этого разработчик может [вручную отслеживать push-уведомления](push-notifications.md#ручное-отслеживание-push-уведомлений).

> ❗️
>
> SDK Flutter в настоящее время не поддерживает отключение автоматического отслеживания push-уведомлений на iOS.

> ❗️
>
> На поведение отслеживания push-уведомлений может влиять функция согласия на отслеживание, которая в включенном режиме требует явного согласия на отслеживание. Подробности см. в [документации по согласию](../doc/tracking-consent).

### Отслеживание токена вручную

Используйте метод `trackPushToken()` (Firebase) или `trackHmsPushToken` (Huawei) для ручного отслеживания токена для получения push-уведомлений. Токен назначается клиенту, который в данный момент вошел в систему (с помощью метода `identifyCustomer`).

Вызов этого метода приведет к немедленному отслеживанию push-токена независимо от значения 'tokenTrackFrequency' (подробности см. в документации [Конфигурация](../doc/configuration.md)).

Каждый раз, когда приложение становится активным, SDK вызывает `verifyPushStatusAndTrackPushToken` и отслеживает токен.

#### Аргументы

| Имя                 | Тип    | Описание |
| ---------------------| ------- | ----------- |
| token **(обязательно)** | Строка  | Строка, содержащая токен push-уведомления. |

#### Пример

Firebase:

```dart
SendsayPlugin().trackPushToken("value-of-push-token")
```

Huawei:

```dart
SendsayPlugin().trackHmsPushToken("value-of-push-token")
```

> ❗️
>
> Не забудьте вызвать [anonymize](#анонимизировать-обезличить) каждый раз, когда пользователь выходит из системы, чтобы гарантировать удаление токена push-уведомлений из профиля пользователя. Невыполнение этого требования может привести к тому, что несколько профилей пользователей будут использовать один и тот же токен, что приведет к дублированию push-уведомлений.

### Отслеживание доставки push-уведомлений вручную

Используйте метод `trackDeliveredPush` для [ручного отслеживания доставки push-уведомлений](../doc/push-notifications.md#отслеживание-доставленных-push-уведомлений).

#### Аргументы

Метод `trackDeliveredPush` принимает в качестве аргумента полезную нагрузку уведомления в формате JSON.

Пример полезной нагрузки см. в разделе [Push notifications](../doc/push-notifications.md#пример-payload).

#### Пример

```dart
SendsayPlugin().trackDeliveredPush(payload)
```

### Отслеживание кликов по push-уведомлениям вручную

Используйте метод `trackClickedPush` для [ручного отслеживания кликов по push-уведомлениям](../doc/push-notifications.md#отслеживание-нажатых-push-уведомлений).

#### Аргументы

Метод `trackClickedPush` принимает в качестве аргумента полезную нагрузку уведомления в формате JSON.

Пример полезной нагрузки см. в разделе [Push notifications](../doc/push-notifications.md#пример-payload).

#### Пример

```dart
SendsayPlugin().trackClickedPush(payload)
```

## Платежи

SDK предоставляет удобный метод `trackPaymentEvent`, который помогает отслеживать информацию о платежах за продукты или услуги в приложении.


### Отслеживание событий платежей

Для отслеживания платежей используйте метод `trackPaymentEvent()`.

#### Аргументы

| Имя                         | Тип          | Описание |
| ---------------------------- -| ------------- | ----------- |
| purchasedItem **(обязательно)** | PurchasedItem | Словарь свойств платежа. |
| timestamp                    | DateTime?     | Временная метка Unix (в секундах), указывающая время отслеживания события. По умолчанию используется текущее время. |

#### Примеры

Сначала создайте объект `PurchasedItem`, содержащий основную информацию о покупке:

```dart
final item = PurchasedItem(
    value = 12.34,
    currency = "EUR",
    paymentSystem = "Virtual",
    productId = "handbag",
    productTitle = "Awesome leather handbag"
)
```

Передайте `PurchasedItem` в `trackPaymentEvent` следующим образом:

```dart
SendsayPlugin().trackPaymentEvent(item)
```

## Свойства по умолчанию

Вы можете [настроить](configuration.md) свойства по умолчанию, которые будут отслеживаться с каждым событием. Обратите внимание, что значение свойства по умолчанию будет перезаписано, если событие отслеживания имеет свойство с тем же ключом.

```dart
final config = SendsayConfiguration(
    projectToken: 'YOUR_PROJECT_TOKEN',
    authorizationToken: 'YOUR_API_KEY',
    baseUrl: 'YOUR_API_BASE_URL', 
    defaultProperties: const {
    'thisIsADefaultStringProperty': 'This is a default string value',
    'thisIsADefaultIntProperty': 1
    },
_plugin.configure(configuration)
```

После инициализации SDK вы можете изменить свойства по умолчанию с помощью метода `SendsayPlugin.setDefaultProperties()`.
